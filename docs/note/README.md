# note 入稿メモ

`online-publisher-pro-note-article.md` を note に貼るための手引きです。書いたのは
連載「教室で使えるかもしれないもの作り」向けの紹介記事で、画像は実際にアプリを
操作して撮ったものです。

このフォルダの中身は、2026年8月に、現在の `index.html` と `code.gs` と `pwa/` に
合わせて撮り直し、書き直したものです。前回そろえたときからアプリの見た目が
変わっていたため、記事も画像もすべて入れ替えてあります。

---

## 1. 貼るまえに直すところ

### 連載番号

タイトルの `#◯` が埋まっていません。何回目になるかを確かめて、数字に置きかえて
ください。ここだけは推測で埋めていません。

```
# 教室で使えるかもしれないもの作り #◯ 「赤ペンの束を持ち帰る夜」をなくす。…
```

### 書き手に撮り足してほしい画像

AI添削を実行した結果の画面だけは撮っていません。手もとにGeminiのキーがなく、
撮影用にそれらしい添削文を作ってしまうと「AIがこう添削した」という事実でない画像に
なってしまうためです。記事では、AI添削の説明に一括処理の確認画面（`13-ai-bulk.png`）を
当てています。実際にキーを入れて動かした画面を1枚足すなら、
「まとめてAI添削」の段落のあとに入れると流れが切れません。

### 気づいたこと（直さなくても公開はできます）

「みんなの作品だな」で、題名の長い作品は縦書きの題名が本のカードからはみ出します。
`19-gallery.png` の「おばあちゃんのおにぎり」がそれです。表示が崩れているだけで、
押せば正しく開きますし、記事の流れにも影響しません。気になるようなら、
本だなのカード側で題名をはみ出させない手当てを別途入れてください。
今回は記事の作成だけを行い、アプリのコードには手を入れていません。

## 2. note への貼りかた

1. note で新しい記事を作り、いちばん上のタイトル欄に `#` の行の中身を貼ります。
   `# ` は外してください。
2. 本文のマークダウンを貼ります。`##` の見出しはそのまま見出しとして認識され、
   note が自動で目次を作ります。
3. 画像は自動では入りません。`images/` の中のファイルを、本文の
   `![…](images/…)` が書いてある位置に手で1枚ずつアップロードしてください。
   貼り終えたら `![…](images/…)` の行は消します。
4. 画像のすぐ下にある一文は、note の画像キャプション欄に移してください。
   本文に残すと画像の説明が二重になります。
5. ハッシュタグは `#GIGAスクール` `#小学校` `#作文` `#教育ICT` `#GoogleAppsScript`
   あたりが記事の中身に合います。

記事は約7,500字です。太字・表・区切り記号は使っていないので、note の
エディタにそのまま流しこめます。

### 画像に写っている作品について

写っている作文と挿絵は、撮影のために書き下ろしたものです。実在する子どもの作品では
ありません。4年1組の6人ぶんと、あまがえるの絵が1枚。記事の本文でも、これらを
教室での実践として語ってはいません。

主役にしている「あまがえるのケロタ」は、次の流れを一本で通して撮りました。
子どもが書いて提出する、先生が2か所に赤を入れて再提出で返す、子どもがコメントを読んで
一文を書き直す、先生が差分を見て完了にする、作品だなに並んで感想が届く。
`14-diff.png` の緑は、この途中で実際に書き足した一文です。

README が古くなっていることがあるので、記事に出した数字はコードで裏を取りました。

## 5. 撮り直すときの手順

このアプリの本体は Google Apps Script の上で動くので、手もとにはスプレッドシートも
ドライブもありません。そこで `code.gs` の各関数をそのままの挙動でメモリ上に移植した
小さなサーバを立てて、`google.script.run` の向き先だけをそこに変えて撮りました。
**画面を作っている `index.html` の React のコードには手を入れていません。**
差しかえたのは、外部から読み込んでいる部品のアドレスと、サーバへのつなぎ先だけです。

撮影に使った一式は `.tmp-shots/` に置いて、納品時に消しました。同じものを作り直す
手順は次のとおりです。

1. 部品を手もとに用意します。CDN がふさがれている環境なので、npm から同じものを
   取ってきて置きかえました。react、react-dom、@babel/standalone、bootstrap-icons、
   diff-match-patch、それに tailwindcss（Play CDN のかわりに CLI で `index.html` を
   走査してCSSを作る）。
   npm から入れるときは `npm i --no-save` を**一度にまとめて**実行します。
   別々に実行すると、あとから入れたものが前のものを消してしまいます。
2. 書体も手もとに置きます。`@fontsource/zen-maru-gothic`
   `@fontsource/shippori-mincho` `@fontsource/zen-old-mincho` を入れて、
   `fonts.googleapis.com` の読み込みをそれに差しかえます。
   Google Fonts に届く環境でも、書体ファイルの取得が途中で切れて明朝体だけ
   落ちることがありました。落ちると縦書きの本モードで文字が重なって写ります。
3. `code.gs` の `saveOrSubmitDraft` `getDraftList` `addGalleryComment`
   `uploadIllustration` `setGeminiApiKey` `updateTeacherPassword` を
   メモリ上に移植したサーバを立てます。`analyzeEssayWithGemini` は
   「キーが未設定」と同じエラーを返すようにしておきます。作り話の添削文を返すと、
   事実でない画像ができてしまうためです。
4. `index.html` の head の読み込み先を1と2で用意したものに向け、
   `google.script.run` を3のサーバに向ける薄い層を1枚かませます。
5. Playwright でシナリオを流します。児童が書いて出す、先生が赤を入れて再提出で返す、
   児童が直す、先生が差分を見て完了にする、作品だなで読み合う、という順に
   一本でたどると、差分や「修正完了」まで自然に撮れます。

撮るときに引っかかったところを残しておきます。

- 一覧や本だなの項目は `button` ではなく `onClick` の付いた `div` です。文字で
  押そうとすると当たりません。
- 縦書きなので、原稿用紙の題名の1列ぶんの要素の文字をつなぐと題名そのものに
  なります。「あまがえるのケロタ」で要素を探すと、モーダルの中ではなく、
  うしろに透けている原稿用紙のほうが先に当たります。モーダルの中だけを見るように
  範囲を絞ってください。
- 見出しの「みんなの作品だな」にはふりがなが入っているので、素朴な文字列一致では
  当たりません。ふりがなを落としてから比べるか、本だなに並ぶ題名で待ちます。
- 印刷の紙面は、ブラウザが印刷を始めるとき（`beforeprint`）に組み立てられます。
  印刷メディアに切り替えただけでは真っ白になります。
- 自動保存は本当に20秒待たないと走りません。待たずに撮ると「編集中」のままです。
- ホーム画面に置く入り口を通信のない状態で開き直しても、保存されている画面が
  そのまま出ます。オフライン用の画面は撮れないので、今回は入れていません。

## 6. 文体について踏襲したこと

連載の書き手のルールに合わせています。機械的に確かめられるところは確認済みです。

- 太字（`**`）を使っていません（0か所）
- 表を使っていません（0行）
- `→` `／` `：` `▲` `▶` を使っていません（すべて0か所）
- マークダウンは見出しだけです
- 箇条書きは手順のところだけに使っています。導入手順の中の
  「フィルタリングで通すアドレス」だけは、情報担当の先生にそのまま渡せる形が
  よいと考えて並べました
- 絵文字は見出しにだけ置いています
- デプロイ、変数、ローカルストレージといった言葉は出していません。
  「公開の設定」「その端末の中に残ります」のように言いかえています
- 本文は約7,500字です

見出しは連載の基本の並びに、目玉が入りきらないぶんとして2本足しました。

```
🏫 はじめに
📱 このアプリでできること
✍️ 原稿用紙の上に、そのまま赤を入れる      ← 足したもの
📚 書いた作文が、みんなで読める一冊の本になる  ← 足したもの
✨ 導入のメリット
🛠️ 【管理者向け】導入手順
📖 【利用者向け】使い方のガイド
📝 まとめ
```

書いていないこともあります。教室での出来事を実体験としては書いていません。
これは作者の実践記録ではないので、「使ってみたら子どもたちが」と書くと嘘に
なるためです。「こうなればいいと思って作った」「〜だと思います」までにとどめて
あります。実際の授業のようすは、書き手が自分の言葉で足すところです。
効果についても言い切っていません。
